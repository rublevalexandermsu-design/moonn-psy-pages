# Спецификация приложения для доступа к API Яндекс Директа

## 1. Назначение приложения

Приложение `Сентея` используется для автоматизации работы с собственными рекламными кампаниями в Яндекс Директе. Основная задача приложения - ускорить регулярные операции рекламного preflight, запуска, мониторинга и оптимизации кампаний для проекта `Мунн / Психология без скуки`.

Приложение не является публичным сервисом для внешних клиентов. Оно используется внутренне владельцем рекламного кабинета и ответственным специалистом по рекламе.

## 2. Какие задачи автоматизируются

Приложение предназначено для следующих сценариев:

- получение статистики по кампаниям, группам, объявлениям и ключевым фразам;
- проверка статусов кампаний, групп и объявлений;
- подготовка и массовая загрузка рекламных материалов через API после ручного согласования;
- обновление ставок и дневных лимитов в рамках заранее согласованных правил;
- остановка или пометка на ручную проверку слабых объявлений, фраз и площадок;
- выгрузка данных для сверки с Яндекс Метрикой и внутренними отчетами;
- контроль UTM-разметки и соответствия посадочной странице.

## 3. Что не делает приложение

Приложение не предназначено для самостоятельного расходования бюджета без контроля владельца кабинета. Публикация кампаний, пополнение баланса, изменение платежных данных и другие финансово значимые действия выполняются только после ручного подтверждения владельцем рекламного кабинета.

Приложение не обрабатывает медицинские данные и не принимает решений по пользователям сайта. Рекламные тексты проверяются в образовательной и информационной рамке.

## 4. Техническая схема работы

1. Пользователь авторизует OAuth-приложение Яндекс ID.
2. Приложение получает OAuth-токен с правом использования API Яндекс Директа.
3. Скрипт или внутренний операторский инструмент отправляет запросы к API Яндекс Директа по протоколу JSON.
4. Данные из Директа сопоставляются с данными Яндекс Метрики, UTM-метками и внутренними отчетами.
5. Все изменения, которые могут повлиять на бюджет, публикацию объявлений или стратегию, проходят ручное подтверждение.

## 5. Протокол и библиотека

- Протокол API: JSON.
- Язык реализации: Python.
- Библиотека: стандартный HTTP-клиент Python `requests`.
- Основной API endpoint: `https://api.direct.yandex.com/json/v5/`.

## 6. Примеры используемых методов API

Планируемые методы:

- `clients.get` - проверка клиента и доступности API;
- `campaigns.get` - получение списка кампаний и статусов;
- `adgroups.get` - получение групп объявлений;
- `ads.get` - получение объявлений и статусов модерации;
- `keywords.get` - получение ключевых фраз;
- `reports` - выгрузка статистики;
- при необходимости после ручного согласования: методы создания и обновления кампаний, групп, объявлений и ставок.

## 7. Логины в Директе

Приложение используется для аккаунта рекламного кабинета, в котором создаются и обслуживаются кампании проекта `Мунн / Психология без скуки`.

Рабочий логин в Директе: `yantaria`.

## 8. Новые возможности для пользователя

Приложение дает пользователю следующие возможности:

- быстрее получать статистику по рекламе без ручной выгрузки из интерфейса;
- регулярно сверять кампании, объявления, UTM-метки и посадочную страницу;
- быстрее находить неэффективные фразы, объявления и площадки;
- готовить массовые изменения перед ручным подтверждением;
- вести более точный контроль заявок, стоимости лида и статусов рекламных материалов.

## 9. Интерфейс приложения

На текущем этапе у приложения нет отдельного публичного пользовательского интерфейса. Работа выполняется через внутренние скрипты и операторский workflow. Основной человеко-читаемый интерфейс остается в веб-кабинете Яндекс Директа, Яндекс Метрике и внутренних отчетных таблицах.

## 10. Безопасность и ограничения

OAuth-токены хранятся локально в защищенном рабочем контуре и не публикуются в открытых репозиториях. Доступ к токенам ограничен рабочей машиной и ответственным оператором.

Финансовые и публичные действия не выполняются полностью автоматически. Для запуска кампаний, пополнения бюджета, публикации объявлений и изменения существенных настроек требуется ручное подтверждение владельца кабинета.

## 11. Демонстрационный доступ

Отдельный публичный демо-доступ к программе не предоставляется, так как приложение является внутренним операторским инструментом для работы с рекламным кабинетом. При необходимости демонстрация возможна через скриншоты сценария работы или совместный просмотр рабочего контура.
